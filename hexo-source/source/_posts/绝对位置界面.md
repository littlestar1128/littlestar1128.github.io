#### 入口函数` Dialog_pos_Abso`

```c
int Dialog_pos_Abso(void)
```

##### 1、函数功能概述

是绝对值界面的入口函数，负责启动整个界面的创建流程：定义界面包含的控件（框架窗口、文本等）、调用框架函数创建对话框窗口、注册消息回调函数，最终将界面展示在屏幕上。  

##### 2、函数参数详解

无参数：该函数作为入口，无需外部传入参数，界面所需的初始配置（如控件位置、默认值）在函数内部定义。

##### 3、返回值

返回值类型：`int`

```c
 含义 ：返回GUI_New_ExecDialogBox(_aDialogCreate1, GUI_COUNTOF(_aDialogCreate1), &_cbCallback, 0, 0, 0) 的执行结果。
```

##### 4、创建一个非阻塞式对话框`GUI_CreateDialogBox`

```c
WM_HWIN GUI_CreateDialogBox (const GUI_WIDGET_CREATE_INFO * paWidget,int NumWidgets, WM_CALLBACK * cb, WM_HWIN hParent, int x0, int y0)
```

```markdown
1) paWidget：指向对话框资源表的指针；

2) NumWidgets：对话框中包含的控件总数；

3) cb：指向对话框回调函数的指针；

4) hParent：父窗口的句柄，为 0 时没有父窗口；

5) x0：对话框相对于父窗口的 X 位置； 

6) y0：对话框相对于父窗口的 Y 位置。 返回值：资源表中第一个控件的句柄。
```

#### 回调函数` _cbCallback`

```c
static void _cbCallback(WM_MESSAGE * pMsg) 
```

##### 1、函数功能概述

`_cbCallback`回调函数中执行的具体操作取决于它接收的消息类型。窗口回调函数中需要构建`switch` 语句， 它使用`case` 语句为不同的消息定义不同的行为。回调函数负责接收并分发所有与界面相关的消息（如初始化、绘制、按键、控件交互等），将不同类型的消息路由到对应的处理函数（如` _initDialog `处理初始化、`paintDialog `处理绘制）。它连接框架事件与业务逻辑的 ，确保每种事件都能被正确响应。

##### 2、函数参数详解

| 参数名 | 类型        | 说明                                                         |
| ------ | ----------- | ------------------------------------------------------------ |
| pMsg   | WM_MESSAGE* | 指向消息结构体的指针，包含事件的所有关键信息：<br/>- pMsg->hWin：目标窗口\当前窗口句柄（标识哪个窗口收到消息）<br/>- pMsg->MsgId：消息类型\消息 ID（如 WM_INIT_DIALOG、WM_PAINT，标识消息类型）<br/>-pMsg->hWinSrc:源窗口\消息源，用于定位事件来源（如哪个按键被点击）<br/>- pMsg->Data：消息附带的数据（如按键编码、控件 ID 等，随消息类型变化） |

##### 3、返回值

返回值类型：`void`（无返回值）
        含义：通过调用对应处理函数（如` _initDialog`）处理消息，无需返回值；未处理的消息会交给框架默认处理函数。

##### 5、相关内部函数

`PageGoto()`跳转窗口  

`GUI_EndDialog()` 结束对话框。

`Theme_GetInput()`获取Maxlen各input控件中的字符并返回

`Theme_ClearInput()`清除所有写入input的内容

`TEXT_SetBkColor()`返回当前文本背景颜色     `PublicFunc_PosFocusWidgetMoveKeyDeal()`移动按键响应

`GetKeyStatus()`得到某键是否被按下

`Theme_UptateKey()`对底部和右侧`button`控件进行更新赋值      在界面切换时会被使用更新button控件内容   调用此函数前一般会有更新结构体`  UI_EFFECT_THEME`中的内容

`HotkeyRespond()`界面切换、字符输入等快捷按键响应

#### 界面恢复函数`_restorePageInfo`

```c
static UI_PAGEINFO *_restorePageInfo(UI_PAGEINFO *pPageInfo)
```

##### 1、函数功能概述

界面状态恢复，负责从持久化存储中读取历史状态数据（如上次输入的坐标、焦点位置、权限设置等），并将这些数据写入到当前界面状态结构体（`pPageInfo`）中，最终返回更新后的状态指针。它确保界面在重新打开、切换或重启后，能恢复到用户上次操作时的状态，提升操作连贯性。解决了界面切换或重启时如何恢复历史态或重置为默认状态。

##### 2、参数同按键响应函数

| 参数名      | 类型           | 说明                                               |
| ----------- | -------------- | -------------------------------------------------- |
| `pPageInfo` | `UI_PAGEINFO*` | 界面状态结构体指针，用于判断按键是否有效及如何响应 |

```c
typedef struct 
{
    unsigned int     level[2];       
    unsigned int     position[2];	 //当前页面标识
    unsigned char    keyRespondFlag; //用户界面事件类型标志，仅为UIEVENT_FUNC时进入
    unsigned int     keyRespondNo;   //按键相应编号(唯一标识当前触发的具体功能，如“坐标切换”“加工时间”)
    UI_EFFECT_THEME  keyEffect;      //各控件的内容
}UI_PAGEINFO;
```

##### 3、返回值

返回值类型：`UI_PAGEINFO*`（指向界面状态结构体的指针）
        含义：返回更新后的` pPageInfo` 指针（与入参相同），便于链式调用（如` _updateDialog`(`_restorePageInfo(&info)->hWin)`）。
        作用：明确告知调用者状态恢复已完成，可直接使用返回的指针操作更新后的状态。

##### 4、使用示例

```c
UI_PAGEINFO* _restorePageInfo(UI_PAGEINFO* pPageInfo) {
    // 1. 空指针保护：如果传入的 pPageInfo 为空，初始化默认结构体
    if (pPageInfo == NULL) {
        pPageInfo = InitPageInfo(pPageInfo); // 初始化 pPageInfo 的所有成员变量
        pPageInfo->position[0] = CURRENTPAGE; // 设置默认页面位置
    }

    // 2. 页面组切换检查：如果页面组不一致，重置位置
    if (CurrentPageGroup != CURRENTPAGEGROUP) {
        pPageInfo->position[0] = CURRENTPAGE; // 重置为当前页面
        CurrentPageGroup = CURRENTPAGEGROUP; // 更新全局页面组标识
    }

    // 3. 设置按键响应标记和功能编号
    pPageInfo->keyRespondFlag = UIEVENT_UPDATE;
    pPageInfo->keyRespondNo = pPageInfo->position[0];

    // 4. 根据当前页面重新计算按键样式
    _getKeyEffect(pPageInfo);

    // 5. 如果需要更新界面主题，同步按键效果
    if (pPageInfo->keyRespondFlag == UIEVENT_UPDATE) {
        Theme_UpdateKey(ThemeHandle, pPageInfo->keyEffect); // 更新主题中的按键样式
    }

    // 6. 返回更新后的状态指针，支持链式调用
    return pPageInfo;
}
```



#### 按键响应函数`_keyRespond`


##### 1、函数功能概述

#### 按键与界面逻辑关系详细总结

##### 1. 界面渲染模块

`_restorePageInfo()：`恢复页面初始状态

- 触发时机：页面首次创建、页面跳转（`PageGoto()`）时；  
- 作用：加载目标页面的基础配置（视图层级、控件默认值、历史状态），为绘制提供初始数据；  
- 最终调用 `paintDialog()` 绘制完整页面，确保页面切换后状态正确。  

`_updateDialog()：`动态触发更新

- 触发时机：业务数据变更（`_FuncKeyRespond()` 后）、视觉样式更新（`_getKeyEffect()` 后）；  
- 作用：刷新界面数据缓存（同步最新业务数据和样式参数），通知系统“需要重绘”；  
- 本质是“数据变更→界面刷新”的桥梁，最终调用 `paintDialog()` 执行实际绘制。  

`paintDialog()：`界面的最终渲染

- 接收 `_restorePageInfo()` 提供的初始数据或 `_updateDialog()` 提供的最新数据；  
- 绘制所有界面元素：图形（主轴状态箭头）、文字（加工数、时间）、控件（按钮、输入框）、刻度线等；  
- 输出：将渲染结果显示到屏幕，是用户可见的“最终交互结果”。  

##### 2. 按键响应模块

`_keyRespond()：`按键交互的前端入口  

- 接收硬件按键信号（键值、按压状态），解析并生成事件标记：  
  - `UIEVENT_FUNC`：业务功能事件（如清零、参数修改）  
  - `UIEVENT_UPDATE`：视觉反馈事件（如焦点切换、按键高亮）  
  - `UIEVENT_GOTO`：页面跳转事件（如切换坐标页、菜单页）  
- 通过 `keyRespondNo` 传递具体业务参数（如“清零功能ID”“跳转目标页ID”），并根据事件类型分发到对应处理函数。  

`_FuncKeyRespond()：`业务逻辑

- 仅响应 `UIEVENT_FUNC` 事件，处理核心业务（如加工数清零、主轴状态切换、参数修改）；  
- 操作两层数据存储：  
  - 内存缓存（`NumParabuf`）：实时生效，用于界面即时显示；  
  - EEPROM（`pGlobal_EEPROM_Data`）：持久化存储，防止掉电丢失关键参数（如累计加工时间）；  
- 业务数据变更后，调用 `_updateDialog()` 触发界面刷新，确保数据与显示同步。  

`_getKeyEffect()：`视觉反馈

- 仅响应 `UIEVENT_UPDATE` 事件，处理交互性操作（如方向键切换焦点、按键长按高亮）；  
- 计算按键视觉样式：背景色、边框状态、文本颜色等，生成 `keyEffect` 样式参数；  
- 通过 `Theme_UpdateKey()` 同步样式到主题系统，最终调用 `_updateDialog()` 触发界面重绘，提供即时视觉反馈。

##### 问题1、界面与F按键（bottom key）是如何关联的？

问题1：按键响应函数`_keyRespond`和F按键是通过下侧功能键键值响应函数`getFuncKeyNo(int key)`将硬件按键的编码转换为自定义的功能键编号。跟宏`CURRENTPAG`存在映射关系。

#####  问题2、F按键下的【操作】按键内的功能按键（时间切换、时间清零等）是如何响应实现的？

问题2：按键响应函数`_keyRespond`标记了三种事件`keyRespondFlag`，事件都是先在回调函数中运行然后再跳转到相应的功能实现函数：

1、功能事件`UIEVENT_FUNC`，在功能按键响应函数`_FuncKeyRespond`中执行，具体根据`keyRespondNo`来执行相应的功能，包括了操作键的功能响应。

2、界面刷新事件`UIEVENT_UPDATE`，在按键效果函数`_getKeyEffect1(UI_PAGEINFO *pPageInfo)`中执行，具体根据`keyRespondNo`来执行相应的功能。    

3、跳转事件`UIEVENT_GOTO`，在回调函数中执行`    PageGoto(hwin, _pPageInfo->keyRespondNo)`跳转到目标界面。

#####  问题3：这些宏`CURRENTPAG`是怎么定义的呢？

问题3：层级设计：

主界面：`CURRENTPAG`绝对坐标

主界面的子界面：对应代码里的 `CURRENT_PAGE*10+1:`，代表 “主界面下的第 1 个子功能 / 子界面”。（相对坐标）

```
												   `CURRENT_PAGE*10+2:`，代表 “主界面下的第 2个子功能 / 子界面”。（绝对坐标）

                                                   `											     CURRENT_PAGE*10+3:`，代表 “主界面下的第 3个子功能 / 子界面”。（综合）

										      	 `CURRENT_PAGE*10+4:`，代表 “主界面下的第 4个子功能 / 子界面”。（程监）

											       `CURRENT_PAGE*10+5:`，代表 “主界面下的第 5个子功能 / 子界面”。（监控）

										      	 `CURRENT_PAGE*10+6:`，代表 “主界面下的第 6个子功能 / 子界面”。（操作）
```

子界面的子界面：`(CURRENT_PAGE*10+6)*10 + 1`，这是 “子界面 6 里的第 1 个更深层功能”，通过再次乘 10 扩展层级。（时间切换）

						   	`(CURRENT_PAGE*10+6)*10 + 2`，这是 “子界面 6 里的第 2 个更深层功能”，通过再次乘 10 扩展层级。（坐标切换）
	
						   	`(CURRENT_PAGE*10+6)*10 + 3`，这是 “子界面 6 里的第3个更深层功能”，通过再次乘 10 扩展层级。（相对清零）
	
						   	`(CURRENT_PAGE*10+6)*10 + 4`，这是 “子界面 6 里的第 4个更深层功能”，通过再次乘 10 扩展层级。（件数清零）
	
						   	`(CURRENT_PAGE*10+6)*10 +5`，这是 “子界面 6 里的第5 个更深层功能”，通过再次乘 10 扩展层级。（时间清零）
