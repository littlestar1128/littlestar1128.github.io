# 单片机 GPIO 引脚配置选择指南

在一次 STM32 矩阵键盘调试中，我遇到过这样的现象：单键扫描正常，某些双键组合却出现电平异常；将扫描列由推挽输出改为开漏输出后，电平恢复正常。问题的关键在于，按键闭合以后，原本看起来彼此独立的输出引脚可能被连接到同一个节点。

这件事提醒我，GPIO 配置需要结合外部电路和工作过程一起判断。以后选择模式时，可以沿着同一条思路检查：**谁负责驱动这根线、无人驱动时电平由谁确定、最坏情况下电压电流是否合规、信号能否及时稳定。**

本文以常见 STM32 GPIO 为例说明选择方法；具体寄存器、复用方式和电气限值，落实到所用型号的数据手册与参考手册。

## 1 先把几项配置分开理解

GPIO 的配置界面经常把多个选项放在一起，但它们解决的是不同问题。

| 配置项 | 决定什么 | 常见选项 |
| --- | --- | --- |
| 引脚功能 | 内部连接到哪里 | 普通 GPIO、外设复用、模拟功能 |
| 数字输入或输出 | 信号由谁提供 | 输入、输出，或由复用外设控制 |
| 输出类型 | 输出级如何驱动线路 | 推挽、开漏 |
| 上下拉 | 驱动器释放时的默认电平 | 无内部上下拉、内部上拉、内部下拉 |
| 输出速度 | 输出边沿适应什么负载和时序 | 低速、中速、高速等，名称随系列变化 |

例如，I²C 引脚常见的是“外设复用 + 开漏输出级 + 外部上拉”。“复用”与“开漏”可以同时成立；外部上拉已经满足要求时，内部上下拉可以关闭。

有些系列将这些选项分开配置，有些系列则将部分配置组合在同一组寄存器位中。尤其要注意 STM32F1 与许多后续系列的区别，后文会单独说明。

## 2 输入模式先看对端如何提供电平

### 对端主动输出高低电平

如果对端是正常工作的推挽输出，高、低电平均由对端主动提供，接收脚通常可以关闭内部上下拉。配置软件中的“浮空输入”或“无上下拉”，表示 MCU 没有接入内部偏置电阻，线路仍然可以被外部驱动到确定电平。

还要检查对端在复位、掉电或未选中时是否会变成高阻。如果会，而接收端又要求确定的默认电平，就应增加合适的偏置。

### 对端只负责拉低或接地

开漏、开集电极输出通常只能主动拉低，释放后需要由上拉恢复高电平。接地按键也是同样的思路：

```text
VDD ── 上拉电阻 ── 输入节点 ── 按键 ── GND
```

按键松开时输入为高，闭合时输入为低。上拉可以来自 MCU 内部，也可以已经存在于外部电路中。

如果按键闭合时接到 VDD，则可采用下拉提供默认低电平。上下拉方向应与电路配合，不能对只会拉低的开漏信号随意选择下拉。

**需要避免的是数字输入节点长期没有确定电平来源。** 输入处于阈值附近或边沿过慢，可能造成额外电流、噪声敏感或重复翻转；施密特输入也不能代替完整的机械按键消抖。[TI CMOS 输入说明](https://www.ti.com/lit/an/scba004/scba004.pdf)

### 模拟信号与未使用引脚

用于 ADC 等模拟功能的脚，应按对应外设要求配置为模拟模式，并检查模拟开关、输入范围、源阻抗和采样时间。能够选择模拟模式，也不代表这根脚一定连接到 ADC 通道。

真正未连接、无需读取的普通 GPIO，通常可配置为模拟模式并关闭内部上下拉，以减少数字输入缓冲带来的功耗；已经连接板上电路的脚，则应按实际连接确定状态。[ST AN4899 第 4.3.4 和 7.1 节](https://www.st.com/resource/en/application_note/an4899-stm32-microcontroller-gpio-hardware-settings-and-lowpower-consumption-stmicroelectronics.pdf)

## 3 推挽与开漏主要区别在于能否主动拉高

### 推挽输出

推挽输出可以主动拉高，也可以主动拉低：

| 输出数据 | 输出级行为 |
| --- | --- |
| 写 0 | 主动拉低 |
| 写 1 | 主动拉高 |

这适合由一个输出端控制的普通数字信号。实际输出电压受负载影响，需要在规定电流下满足数据手册中的 `VOH`、`VOL`，不能把写 1、写 0 简单理解为始终精确等于电源或地。

关键检查是：**在任何工作状态下，这根线上是否可能同时出现另一个主动驱动器。** 按键、跳线、连接器和外设状态变化，都可能把原本独立的线路连通。两个推挽输出一高一低时，会出现输出争用，节点电压和电流都不能依赖正常逻辑输出条件来保证。

### 开漏输出

开漏输出只主动拉低；写 1 时关闭拉低通路，释放线路：

| 输出数据 | 输出级行为 | 引脚实际电平 |
| --- | --- | --- |
| 写 0 | 主动拉低 | 在负载允许范围内接近地 |
| 写 1 | 高阻释放 | 由上拉、外部驱动及连接状态决定 |

因此，**输出级高阻描述的是“自己不再驱动”，高电平描述的是线路最后呈现的电压**。有上拉且没有其他器件拉低时，线路才会上升为高电平；即使输出数据写了 1，也可能从输入寄存器读到低电平。

多个兼容的开漏端可以共用一条线路，任意一方拉低时，线路就为低。这是常规 I²C 使用开漏和上拉的重要原因；实际连接仍需满足总线电压、电流及协议要求。[NXP I²C 规范第 3.1.1 节](https://cache.nxp.com/docs/en/user-guide/UM10204.pdf)

“开漏必须上拉”应理解为：**如果需要释放后得到确定的数字高电平，就需要有效的上拉来源。** 上拉可以已在电路其他位置，某些专用器件也提供有源上拉；开漏仅用于控制某个负载的通断时，还要按负载电路分析，不能机械地给每个开漏脚再加一只电阻。

## 4 上下拉电阻要兼顾电平 电流与时序要求

内部上下拉通常是弱偏置，阻值范围及其供电、温度条件应查具体型号。短线低速按键可以从内部上拉开始验证；需要在 MCU 初始化以前就确定电平、线路电容较大，或抗干扰要求更高时，外部电阻更便于设计。

阻值减小时，线路恢复高电平更快，但拉低时电流也会增加。以 3.3 V、10 kΩ 上拉为例，忽略低电平残压，拉低电流约为：

```text
I ≈ 3.3 V / 10 kΩ = 0.33 mA
```

同一条线上已有多个上拉时，应按并联后的等效阻值计算。矩阵键盘多键导通时，也要计算被选中列可能吸收的各路上拉电流之和。

### I²C 上拉的计算示例

对于普通无源电阻上拉、可近似为集中 RC 的 I²C 线路，常用边界是：

```text
Rmin = (Vpullup − VOLmax) / IOL
Rmax = tr_max / (0.8473 × Cbus)
```

`IOL` 取线上最弱拉低器件在规定 `VOL` 下保证的灌电流能力；`Cbus` 包含引脚、走线、连接器等总电容。系数 `0.8473` 对应 30%～70% 的上升时间。[TI 上拉电阻计算说明](https://www.ti.com/lit/an/slva689/slva689.pdf)

假设 `Vpullup=3.3 V`、`VOLmax=0.4 V`、`IOL=3 mA`、`Cbus=100 pF`，要求 `tr≤300 ns`，则：

```text
Rmin ≈ 967 Ω
Rmax ≈ 3.54 kΩ

2.2 kΩ：tr ≈ 186 ns
4.7 kΩ：tr ≈ 398 ns
```

这个例子中，4.7 kΩ 就不满足给定的上升时间要求。实际选值还要留出电源、电阻、电容公差和漏电余量。

普通 STM32 I²C 工程通常使用经过计算的外部上拉；普通 GPIO 弱上拉与专用有源上拉的能力不同。使用集成电流源或上升沿加速器时，应按器件与总线规范另行分析。[NXP I²C 规范](https://cache.nxp.com/docs/en/user-guide/UM10204.pdf)

## 5 分别检查输出速度与电气兼容性

### 输出速度选择满足时序的较低档位

STM32F1 的 `2 MHz`、`10 MHz`、`50 MHz` 等名称，对应一定供电和负载条件下的输出能力与边沿特性。选为 `50 MHz` 不会自动让引脚以 50 MHz 翻转，也不意味着可以随意增加直流负载。具体上升、下降时间应查数据手册的 I/O AC 表。[STM32F103xC/D/E 数据手册第 5.3.14 节](https://www.st.com/resource/en/datasheet/stm32f103ze.pdf)

按键扫描、指示灯控制等低速用途，通常从低速档开始；高速外设则结合频率、负载和接收端时序选取。边沿过陡会增加振铃、串扰和 EMI 风险；纯输入模式的输出速度设置不会提高输入采样速度。I²C 的无源上拉上升沿主要受 RC 影响，提高 GPIO 输出速度也不能替代调整上拉和总线电容。[ST AN4899 第 4.3.1 和 7.2 节](https://www.st.com/resource/en/application_note/an4899-stm32-microcontroller-gpio-hardware-settings-and-lowpower-consumption-stmicroelectronics.pdf)

### 5 V 容忍与逻辑兼容分别确认

判断两个器件能否互连，至少检查两类条件：

| 检查内容 | 要确认的问题 |
| --- | --- |
| 耐压与工作条件 | 这个具体引脚，在当前模式、供电和上电顺序下，是否允许该输入电压 |
| 逻辑电平 | 发送端保证的 `VOH/VOL`，是否满足接收端要求的 `VIH/VIL` |

FT 标记不提供 5 V 输出能力，也不能自动保证掉电时仍可承受外部 5 V。例如，若某 5 V 接收端要求 `VIH≥0.7×VDD=3.5 V`，理想的 3.3 V 高电平也不足以满足它；这里的阈值是示例条件，实际应查接收器数据手册。

开漏上拉到 5 V，同样需要逐个检查线上器件的引脚耐压、模式、内部上下拉和掉电条件。以 STM32F103xC/D/E 为例，数据手册要求承受高于 `VDD+0.3 V` 的输入时关闭内部上下拉。**绝对最大额定值也不能当成正常设计工作点。** [STM32F103xC/D/E 数据手册](https://www.st.com/resource/en/datasheet/stm32f103ze.pdf)

### GPIO 控制负载前检查驱动级

小电流 LED 可以在限流和引脚电流预算允许时直接控制；普通继电器线圈、电机等负载通常通过晶体管或驱动芯片控制，并为感性关断电流提供续流或钳位路径。带驱动电路的模块则检查其逻辑输入规格。[TI 继电器驱动说明](https://www.ti.com/document-viewer/lit/html/slvaf04)

MOSFET 栅极是否适合直接由 GPIO 控制，要看实际栅压下的导通电阻、栅极电荷和开关频率。`VGS(th)` 表示开始导通的条件，不能直接当成充分导通所需的驱动电压。

## 6 矩阵键盘案例为什么改成开漏后正常

这个案例使用 6×8 矩阵：PE0～PE5 为行输入，PE7～PE14 为列输出。扫描时逐列拉低，再读取所有行，按下为低电平有效。

### 推挽输出可能通过按键形成争用

假设同一行上有两个键，分别连接 C1 和 C2。扫描 C1 时，如果 C1 推挽输出低、C2 推挽输出高，两个键同时闭合就会形成通路：

```text
C2 的高电平驱动器 → 按键 B → 同一行 → 按键 A → C1 的低电平驱动器
```

高电平端提供拉电流，低电平端吸收灌电流，两个输出互相争用。节点可能落在输入阈值附近；具体电压受输出特性、供电、负载和连接电阻影响，不能假设一定为电源的一半。

某颗芯片暂时还能识别，并不能说明这种连接满足设计要求。这里应消除争用通路，而不是依靠某个 IO 恰好“拉得更低”。这是根据按键连通关系与推挽输出结构得到的电路分析。

### 开漏使未选中列释放线路

改为开漏后，当前列写 0 拉低，未选中列写 1 释放。未选中列不再主动拉高，被选中列只需吸收通过上拉流入的有限电流。

| 引脚 | 在本扫描方式中的作用 | 配置思路 |
| --- | --- | --- |
| PE0～PE5 | 读取行状态 | 数字输入，具有有效上拉 |
| PE7～PE14 | 逐列选择 | 开漏输出，当前列写 0，其他列写 1 |

行端可以使用内部上拉；已有适当外部上拉时，也可以关闭内部上拉。需要确定默认高电平的是被读取的行输入。

从扫描功能推导，列写 1 的目的在于释放，因此行端已有上拉时，并不必然要求每根列线再单独装一只上拉。但是，未连接闭合按键的释放列可能悬空，其数字输入缓冲仍可能带来功耗或噪声问题；需要列端确定电平时，应按芯片能力和负载设计列上拉。[ST AN4899 第 6.4 节](https://www.st.com/resource/en/application_note/an4899-stm32-microcontroller-gpio-hardware-settings-and-lowpower-consumption-stmicroelectronics.pdf)

### STM32F1 配置示例

下面使用 STM32F1 标准外设库，适用于对应封装提供这些引脚、且未被其他功能占用的工程。外部上拉及其电流预算应与实际原理图配合。

```c
void Keyboard_GPIO_Init(void)
{
    GPIO_InitTypeDef gpio;

    const uint16_t row_mask =
        GPIO_Pin_0 | GPIO_Pin_1 | GPIO_Pin_2 |
        GPIO_Pin_3 | GPIO_Pin_4 | GPIO_Pin_5;

    const uint16_t col_mask =
        GPIO_Pin_7  | GPIO_Pin_8  | GPIO_Pin_9  | GPIO_Pin_10 |
        GPIO_Pin_11 | GPIO_Pin_12 | GPIO_Pin_13 | GPIO_Pin_14;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOE, ENABLE);

    /* 先预置列输出数据为 1，切入开漏输出后即为释放。 */
    GPIO_SetBits(GPIOE, col_mask);

    GPIO_StructInit(&gpio);

    /* 行输入：这里采用内部上拉。 */
    gpio.GPIO_Pin = row_mask;
    gpio.GPIO_Mode = GPIO_Mode_IPU;
    GPIO_Init(GPIOE, &gpio);

    /* 列输出：开漏；扫描用途从低速档开始。 */
    gpio.GPIO_Pin = col_mask;
    gpio.GPIO_Mode = GPIO_Mode_Out_OD;
    gpio.GPIO_Speed = GPIO_Speed_2MHz;
    GPIO_Init(GPIOE, &gpio);
}
```

**F1 的开漏输出模式不能同时启用内部弱上拉。** F1 使用 `CRL/CRH` 的 `MODE/CNF` 选择模式，输入上下拉由 `ODR` 选择；若需要列端上拉，应采用外部电阻。许多后续系列具有独立 `PUPDR`，可以分别配置输出类型和上下拉。同样使用 HAL，也不会改变芯片本身的硬件能力。[ST 官方 STM32F1 GPIO 驱动源码](https://github.com/STMicroelectronics/stm32f1xx-hal-driver/blob/master/Src/stm32f1xx_hal_gpio.c)

以扫描 PE7 所在列为例，两次写操作应这样理解：

```c
uint16_t col_pin = GPIO_Pin_7;

GPIO_ResetBits(GPIOE, col_pin);  /* 开漏主动拉低 */
/* 在这里等待电平稳定，然后读取行输入。 */
GPIO_SetBits(GPIOE, col_pin);    /* 开漏释放，实际电平由电路决定 */
```

### 分别处理输出争用与鬼键及机械抖动

开漏避免了这个案例中的强高与强低争用，但无隔离二极管的矩阵仍可能出现鬼键：三个闭合键占据一个矩形的三个角时，连通路径可能使未按下的第四角也被识别。逐键二极管可以阻断相应反向通路；软件屏蔽有歧义组合则会限制可报告的按键组合。[TI TCA8418 矩阵键盘说明第 9.1.1 节](https://www.ti.com/lit/ds/scps215e/scps215e.pdf)

同一行两键闭合时，未选中列被间接拉低，本身不能证明出现了鬼键，更不能据此断定一定存在“半电平分压”。机械抖动则是另一类随时间变化的问题，需要单独消抖。

本次案例的实际修改集中在 GPIO 配置；讨论过的消抖方案不作为已经实施的修改记录。

## 7 上电复位及未使用状态的配置

GPIO 初始化只决定程序执行到该位置以后的状态。继电器使能、MOSFET 栅极、片选等关键控制线，在上电和复位期间也需要确定电平；应结合外部偏置、芯片复位默认状态与供电顺序设计。

对于普通 GPIO 输出，可在时钟使能后先预置输出数据，再切换输出模式，以减少不希望的瞬态；外设复用还需配合外设自身的使能与输出时序。具体寄存器顺序按对应参考手册执行。

处理“未使用引脚”前，先确认它确实没有板级用途。SWD/JTAG、复位、启动、晶振、唤醒及连接外部器件的脚，均不能只因当前业务代码没用到，就统一设成输出低或模拟模式。

## 8 常见场景速查

| 场景 | 配置起点 | 需要进一步确认 |
| --- | --- | --- |
| 接地按键 | 输入，内部或外部上拉 | 抖动、线路干扰、上拉电流 |
| 对端推挽数字信号 | 输入或对应外设接收配置 | 对端高阻期间的偏置、逻辑阈值 |
| 开漏中断线 | 输入，有效上拉 | 所有连接器件的电压和灌电流 |
| 小电流 LED | 推挽或合适的灌电流连接 | 限流电阻、单脚及总电流预算 |
| 继电器或电机 | GPIO 控制驱动级 | 驱动器、默认关闭状态、感性钳位 |
| 常规 I²C | 外设复用开漏，上拉网络 | 等效上拉、电容、上升时间、电压域 |
| UART TX | 外设发送配置，通常为推挽 | 对端阈值、空闲和复位电平 |
| UART RX | 对应外设接收配置 | 对端释放时是否需要上拉 |
| SPI 主机 SCK/MOSI | 外设输出，通常为推挽 | 主从角色、负载与时序 |
| SPI 主机 MISO | 外设接收配置 | 从机未选中时的高阻与默认电平 |
| ADC 通道 | 模拟功能，通常无内部上下拉 | 通道连接、量程、源阻抗、采样时间 |
| 本文矩阵键盘 | 行输入上拉，列开漏扫描 | 列偏置、最坏灌电流、鬼键与消抖 |
| 真正未连接的普通 GPIO | 通常模拟模式，无内部上下拉 | 低功耗、调试和唤醒要求 |

表中的外设接收配置要按系列落实：许多较新 STM32 的 UART RX、SPI MISO 也需要选择对应 AF；STM32F1 则采用其自身的输入配置和 AFIO 映射方式。SPI 从机的引脚方向还应按从机角色重新判断。

每次遇到新引脚，可以按以下顺序留下设计记录：

1. 写清它连接的器件、引脚及电压域，并确认封装和复用功能支持。
2. 标出工作、复位、掉电、未选中期间，谁会主动驱动或释放线路。
3. 确定推挽、开漏或输入，以及释放时默认电平由谁提供。
4. 从数据手册核对逻辑阈值、耐压、保证输出电流和端口总电流限制。
5. 计算或验证偏置电阻、负载及边沿时间，选择合适输出速度。
6. 测量接收端实际波形，覆盖多键、负载变化和上电过程等相关状态。

这样留下的记录既解释了配置结果，也保留了选择它的条件，后续更换芯片、外设或连接方式时就有依据可查。
